# 부트캠프 검증 1주 압축 플랜

작성일: 2026-05-24 (일)
실행: 2026-05-25 (월) ~ 2026-05-31 (일)
원문서: `uploads/AgentPayroll_부트캠프_검증_리source_플랜.md` (4주 플랜)
압축 사유: 부트캠프 막판 응답률 폭락 리스크 — 늦으면 검증 자체 불가.

> 핵심 원칙: **코드 작업은 최소화, 인터뷰가 메인.** 인터뷰 0건이면 코드를 아무리 잘 짜도 검증은 0. 코드는 *인터뷰 응답을 받기 위한 미끼*(가짜 리포트, 데모 데이터)와 *결과 정리*용으로만 쓴다.

---

## 결정 사항 (사용자 확인 완료)

- 부트캠프 6팀의 실제 페르소나는 **아직 모름**.
- 가상 데이터는 **Generic Team A ~ Team F**로 시작.
- 인터뷰 직후(Day 3~4, 3~4일차) 진짜 팀명·feature(제품 기능)로 `bootcampSample.ts`를 swap(샘플 데이터 교체).

## 1주 일정 (요일 단위)

### Day 1(1일차) — 월 (2026-05-25): 양해 + 미끼 준비
**목표: 코드 0줄, 메시지 2개, 미끼 1장.**

| 시간 | 행동 | 산출물 |
| --- | --- | --- |
| 오전 | 운영진/강사 1:1 양해 메시지 발송 (`docs/research/bootcamp-slack-messages.md` §1) | 운영진 인지 + 공식 활동 처리 |
| 오전 | 운영진 OK 받으면 즉시 팀 채널/그룹 메시지 발송 (§2) | 인터뷰 신청 3~5건 목표 |
| 오후 | 우리 앱 `?sample=bootcamp` 모드로 가짜 리포트 PNG 1장 export | 인터뷰 미끼 (이미지 1장) |
| 저녁 | 인터뷰 일정 확정 (Day 2~3에 3건 이상) | 캘린더 |

**Day 1 종료 조건**: 인터뷰 3건 이상 확정 + 가짜 리포트 1장 준비 완료. 둘 다 못 했으면 Day 2를 추가 outreach(추가 연락/섭외)로 사용.

### Day 3(3일차) — 수 (2026-05-27): 인터뷰 2~3건 + 페르소나 swap(교체) 결정
**목표: 인터뷰 누적 3~5건 + 코드 swap(데이터 교체) 시작.**

| 시간 | 행동 | 산출물 |
| --- | --- | --- |
| 종일 | 인터뷰 2~3건 진행 | 기록 |
| 저녁 | 인터뷰 결과로 `bootcampSample.ts` 교체 — *2단계*: (a) 팀명/plan/feature 라벨 교체, (b) 분포 가정 재교정 (risk band, time profile, feature weights, 모델 mix). 인터뷰에서 자연스럽게 나온 *추정 호출 수/모델/사용 빈도*만 반영하고, 안 나온 부분은 그대로 둠 | bootcampSample.ts v2 |

**Day 3 종료 조건**: 인터뷰 누적 3건 이상 + 데이터 swap 1차 완료. 인터뷰가 2건 이하면 Day 4에 추가 1~2건 reschedule(일정 재조정).

## 안 할 것 (Anti-checklist, 하지 않을 일 목록)

- ❌ SDK(개발자가 붙이는 자동 수집 도구) 진짜 구현. 인터뷰 응답 수용도만 측정.
- ❌ 부트캠프 모드 진입 UI 새로 짜기. `?sample=bootcamp` 파라미터로 기존 import 흐름 재활용.
- ❌ 운영진/팀에게 가격 직접 묻기 ("얼마 내실래요?"). WTP 약신호만 수집.
- ❌ Wedge A(설계 시점 1인 창업자) 시나리오 폐기. *이번 검증은 Wedge B(운영 후 실제 로그 기반 분석) 한정*임을 부록에 명시.
- ❌ 외부 LLM 문서의 "CSV를 Historical Import로 격하" 제안 채택. 부트캠프 환경 자체가 CSV가 자연.
