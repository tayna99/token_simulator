# 부트캠프 인터뷰 가이드 + 기록 템플릿

작성일: 2026-05-24
사용: Day 2~3 인터뷰 진행 시.
원칙: **10분 안에 끝낸다. 7개 질문 + 1개 옵션. 원문 발언 별표.**

---

## 인터뷰 진행 흐름 (10분)

```
[0~1분]  서로 인사 + "녹음 아니고 메모만 남깁니다" 확인
[1~3분]  질문 1~3 (API 사용 계획 + 비용 감각)
[3~6분]  질문 4~5 (관리 방식 + 의사결정)
[6~9분]  질문 6~7 (리포트 가치 + privacy)
[9~10분] 옵션 질문 (SDK 수용도) + 감사 인사
```

**진행 팁**
- 답변이 길어지면 끊지 말고 *다음 질문으로 넘어가는 자연스러운 다리*를 만들기. 예: "그 부분 흥미롭네요, 그러면 혹시 ~?"
- 정량 점수(1~5)는 *답변 후 본인이 매김* — 인터뷰 중 "이거 1~5점 중 몇이실까요?" 한 번만 묻기.
- "잘 모르겠어요"는 *가장 가치 있는 답*. 절대 도와주지 말 것 ("음 이건 보통 이렇지 않나요?" 같은 유도 금지).

---

## 7개 핵심 질문

### Q1. API 사용 계획 (사용 기능 파악)

> "이번 프로젝트에서 OpenAI API를 어떤 기능에 쓸 예정이에요?"

- **얻고 싶은 것**: feature taxonomy (실제 기능 카테고리)
- **다음 질문 다리**: "그중에서 가장 자주 호출될 거 같은 게 뭐예요?"

---

### Q2. 비용 예측 감각 (가설 1 검증)

> "한 달에 10만 원 한도가 있는데, 어느 정도 쓸 거 같으세요?"
> *(잘 모르겠다는 답이 나오면)* "예상이 안 가시는 게 자연스러운가요, 아니면 알 수 있어야 한다고 생각하세요?"

- **얻고 싶은 것**: 비용 예측 가능성에 대한 *본인의 자각*.
- **성공 신호**: "잘 모르겠어요" + "써봐야 알 거 같아요" + "감이 안 와요"
- **실패 신호**: "한도 안에서 충분히 쓸 수 있을 거예요" (자신감) — 이런 답이 많으면 우리 문제의식 약함.

---

### Q3. 비용 분포 인지 (가설 2 검증)

> "어떤 기능이 API 비용을 가장 많이 쓸 것 같아요? 그 이유는요?"

- **얻고 싶은 것**: 기능별 비용 추측 능력 + 추측의 근거.
- **성공 신호**: "막연한데… 호출이 많은 거?" / "잘 모르겠는데 음성이 비쌀 거 같아요" (구체성 부족)
- **실패 신호**: "토큰 단위로 계산해서 X 기능이 Y%이고…" (이미 이해도 높음)

---

### Q4. 모니터링 방법 (가설 3 검증)

> "사용량 80% 도달 전에 팀 내부에서 *미리* 알 수 있는 방법이 있어요?"

- **얻고 싶은 것**: 자체 모니터링 부재 확인.
- **성공 신호**: "콘솔 보고요" / "그냥 가끔 확인해요" / "OpenAI에서 메일 와야 알 거 같은데요"
- **실패 신호**: "스크립트로 매일 체크해요" / "대시보드 만들어놨어요"

---

### Q5. 의사결정 시나리오 (Decision Layer 검증)

> "비용이 예상보다 많이 나오면 어떤 결정을 할 것 같아요?
> 모델 변경, 기능 축소, 호출 제한, 캐싱 중에 어느 게 먼저예요?"

- **얻고 싶은 것**: 결정 옵션의 *우선순위 감각*.
- **성공 신호**: 1순위가 명확 ("모델 바꿀 거 같아요") + 이유 1~2문장. → AgentPayroll의 decision-first UX 가치 검증.
- **실패 신호**: "음… 다 해볼 거 같은데" (선택 압박 없음) — 이러면 우리 *decision-first* 포지셔닝 약함.

---

### Q6. 리포트 가치 (가설 5 검증) ★

> "프로젝트 끝나고 발표/제출할 때 'AI 사용 리포트'가 있으면 도움이 될까요?
> 어떤 내용이 들어가면 좋겠어요?"

- **얻고 싶은 것**: 발표/제출 문화 → 리포트 니즈 매칭.
- **성공 신호**: "그거 있으면 발표에 쓸 수 있겠는데요" + 항목 2개 이상 자발 언급.
- **실패 신호**: "발표는 그냥 PPT면 돼요" — 이러면 우리 export 기능 약화.
- **★ 표시 이유**: 가장 강한 승산 항목. 여기 답변은 *원문 그대로 받기*.

---

### Q7. Privacy / prompt 수집 민감도

> "사용량/모델/기능명만 자동으로 기록되고, **prompt 내용은 안 가져가는** 도구가 있으면 어떠세요?
> 안심되세요, 아니면 prompt도 봐야 의미 있다고 생각하세요?"

- **얻고 싶은 것**: prompt-free analytics 포지셔닝 검증.
- **성공 신호**: "그 정도면 괜찮은데요" / "prompt 가져가면 부담스러워요" — 우리 포지션 강함.
- **실패 신호**: "prompt도 같이 봐야 디버깅되지 않나요?" — observability 영역에 가깝다는 신호.

---

### 옵션 Q. SDK + 가격 약신호 (인터뷰 끝나고 DM으로 별도)

> "이런 정보를 SDK 한 줄로 자동 수집해주는 도구가 있다면,
> 한 달에 *1만 원 정도면* 쓸까요?"

- **얻고 싶은 것**: WTP 약신호 + SDK 수용도.
- **성공 신호**: "그 정도면 가입할 거 같은데요" / "1만원이면 부담 없죠"
- **약신호**: "잘 모르겠는데 일단 보고 결정할 거 같아요"
- **실패 신호**: "지금 단계에서는 안 쓸 거 같아요"

## 운영진 인터뷰용 추가 질문 (Day 3 저녁)

운영진 인터뷰는 *5문항으로 더 짧게*.

| # | 질문 | 얻고 싶은 것 |
| --- | --- | --- |
| 1 | "팀별 API 사용량/잔액을 지금은 어떻게 확인하세요?" | 현재 모니터링 도구 |
| 2 | "80% 도달 알림을 받은 뒤 어떤 결정을 하세요? 추가 충전, 사용 제한, 다른 팀 가속화 등?" | admin decision layer |
| 3 | "팀별 사용처(어떤 기능에 많이 썼는지)가 보이면 운영에 도움이 되실까요?" | feature attribution 가치 |
| 4 | "다음 부트캠프 때 *같은 문제*가 또 생긴다면 어떤 도구가 있으면 좋겠어요?" | recurring need 검증 |
| 5 | "예산 분배 결정에 데이터를 더 쓰고 싶다는 생각 있으세요, 아니면 현재 방식으로 충분하세요?" | data-driven culture 측정 |

## 인터뷰 끝나고 *바로* 할 일

1. 5분 안에 기록 템플릿 채우기 (기억 사라지기 전).
2. **원문 발언 ★ 표시한 것** 별도로 `bootcamp-quotes-for-landing.md`에 모으기.
3. 가설 매핑 표 채우기.
4. 다음 인터뷰까지 15분 휴식 (인터뷰는 *집중력 소모* 큰 활동).

---

## Don'ts

- ❌ "저희 제품에는 X 기능이 있는데요…" — 제품 소개 금지.
- ❌ "이거 어떠세요?" 5번 이상 — 유도 질문 누적.
- ❌ 가설을 미리 말함 — "저는 이런 가설을 검증 중인데요" 금지.
- ❌ 응답자의 답에 끄덕끄덕하며 동의 표현 — 사회적 압박 생성.
- ❌ 10분 초과 — 본인이 지치고 응답자도 지침. 다음 인터뷰 망함.

---

## Do's

- ✅ 침묵 5초 견디기. 응답자가 채울 때 가장 솔직한 답이 나옴.
- ✅ "왜 그렇게 생각하세요?" 1~2회만 사용.
- ✅ "지금 한 말 그대로 인용해도 될까요?" — 원문 발언 확보용.
- ✅ "잘 모르겠어요"에 "그것도 좋은 답이에요" 반응 — 솔직함 보상.
- ✅ 마지막에 "혹시 제가 안 물어본 거 중에 중요하다고 생각하시는 거 있어요?" — *예상 못 한 신호*가 여기서 나옴.
