# AI 팀원 운영 시나리오 + HITL 사례

> §1 [보완] 항목: 오케스트레이션/HITL 사례 + "도구 아닌 팀원" 서사.
> 공통 루프: **위임(사람) → 실행(AI) → 검수(Rule·Trust·근거) → 승인(사람) → 원장 기록**. 색 규칙: 사람=결정·승인만, AI=자율 수행(정규화·진단·후보·근거).

---

## 시나리오 1 — 원장·데이터 (usage_data_ingestion + trust_security)
- **위임**: 사람이 사용량 CSV 업로드.
- **실행(AI)**: 컬럼을 정규화 테이블로 매핑, 고객/기능/모델/세션 귀속, 비용 폴백(explicit→model_price).
- **검수**: Trust가 PII·원프롬프트·API키 감지 → 차단/리댁션 후보. health 상태(ready/needs_mapping).
- **승인(사람)**: 리댁션 승인 → 스냅샷 확정.
- **전→후**: 뒤죽박죽 엑셀 → 정규화·귀속된 사용 장부.
- **사람 개입점**: 리댁션 승인, 매핑 모호 시 확인.

## 시나리오 2 — 자문·진단 (customer_diagnostic_pricing + finance_ops) ★대표
- **위임**: "이번 달 적자 고객 찾아줘."
- **실행(AI)**: 고객별 마진 진단, 적자·집중 위험 고객 식별, credit/cap 정책 후보 + 리스크 카드 제시.
- **검수**: 숫자는 결정론 엔진, 근거(ref)·리스크 카드 첨부. 인용 없는 숫자는 가드로 폴백.
- **승인(사람)**: Adopt / Reject / Hold 명시 선택 → 결정 원장 기록 → 리포트 잠금 해제.
- **전→후**: "누가 적자인지 모름" → 결정과 근거가 남은 한 장.
- **사람 개입점**: Adopt/Reject/Hold, 리포트 공유 여부.

## 시나리오 3 — 최적화 (optimization_routing)
- **위임**: "비용 줄일 데 있어?"
- **실행(AI)**: model-switch·prompt-caching·batch·output-cap·routing 레버를 절감액순 랭킹 + **품질 리스크** 표기.
- **검수**: 각 레버에 예상 절감·품질 영향 근거.
- **승인(사람)**: 품질 리스크 수용 여부 결정 → 라우팅 권고(프리뷰/승인).
- **전→후**: 막연한 "비싸다" → 우선순위 매겨진 절감 레버.
- **사람 개입점**: 품질 저하 감수 결정.

## 시나리오 4 — 가격 (pricing_revenue_ops)
- **위임**: "이 플랜 마진 괜찮아? 요금 어떻게?"
- **실행(AI)**: flat/credit/cap/hybrid/overage 시나리오 계산 + rate card 초안.
- **검수**: 시나리오별 마진·민감도, 근거.
- **승인(사람)**: 승인 시 rate card draft. **빌링 푸시는 승인 전 차단**(상태기계).
- **전→후**: 감으로 가격 → 시나리오·초안으로 의사결정.
- **사람 개입점**: 정책 채택, 빌링 연동 승인.

## 시나리오 5 — 리서치·보증 (provider_api_intelligence)
- **위임**: (정기) 공급사 가격·조건 최신인지 확인.
- **실행(AI)**: watchtower가 가격 변동 감지, freshness 플래그, 출처(source:…) 수집.
- **검수**: baseline_unavailable / needs_review 정직 표기.
- **승인(사람)**: 새 fact를 Fact Ledger에 수락 → 계산에 반영.
- **전→후**: 옛 가격으로 계산 → 검증·수락된 최신 단가.
- **사람 개입점**: fact 수락.

## 시나리오 6 — 재무·도그푸딩 (finance_ops) ★Spark Claw 핵심
- **위임**: (월말) "내 AI팀 운영 원가·런웨이 정리해줘."
- **실행(AI)**: 자체 서빙 원가·에이전트별 비용·런웨이 집계.
- **검수**: 비용 출처·가정.
- **승인(사람)**: 런웨이·예산 결정.
- **전→후**: 내 비용 깜깜이 → **내 제품으로 내 AI팀을 측정**한 운영 손익.
- **사람 개입점**: 예산·런웨이 결정.

## "도구 아닌 팀원" 서사

도구는 *사람이 매번 직접 호출하고 결과를 직접 계산*한다. 팀원은 *역할·권한·책임·검수 루프*를 갖는다. 위 6개 시나리오에서 AI는 **자율적으로 수행**(정규화·진단·후보·근거·집계)하고, 사람은 **결정·승인만** 한다.

이게 도구 사용이 아니라 직원 운영체계인 이유 — 6요소가 다 있다:
1. 역할 정의(11 에이전트) 2. 권한 매트릭스 3. read-only 경계 4. 검수·승인 게이트(Adopt/Reject/Hold) 5. 운영 케이던스(일/주/월/분기) 6. eval 지표(rework·스키마 통과율·증빙 커버리지).

**한 문장**: "나는 AI를 호출하지 않는다. 나는 AI 팀을 *운영*한다 — 역할·권한·검수·승인·평가로."
